# ITEM_INFO 解析回归收口设计

## 目标

修复原始采集载荷通过 `raw_records` 进入独立解析服务时，大写 `ITEM_INFO` 商品文字未被识别且 `original_text` 为空的问题，同时保持现有 `packageItemDetail`、多商品拆行、特殊单和数量统计行为不变。

## 范围

- 只修改独立解析服务的原始载荷商品文字读取逻辑。
- 增加从 `/api/v1/parse/batch` 真实入口进入的回归测试。
- 不修改前端、后端适配器、数据库结构、采集器、生产规则包或现有业务数据。
- 不改变 HTTP 合同，部署时只替换解析服务。

## 数据流与优先级

1. 规则包声明的 `structured_item_sources` 继续优先解析 `packageItemDetail[]`。
2. 结构化来源没有结果时，现有原始载荷文本兜底读取同时接受 `itemInfo` 和 `ITEM_INFO`。
3. `ITEM_INFO` 仍经过现有 `parse_item_text`，不新增第二套解析算法。
4. 只要存在可读商品文字，订单行的 `original_text` 必须保留该文字；不能显示“有文字”但原文为空。

## 回归门禁

使用脱敏后的任务45结构覆盖：

- 一条原始记录包含4个 `ITEM_INFO` 文档，必须输出4个父面单和4个订单行。
- 每行必须有商品、销售属性、尺码、数量和非空原文。
- 另一条单文档 `ITEM_INFO` 必须同样正常。
- 现有 `packageItemDetail` 多商品测试必须继续通过。
- 部署前只读比较任务45：面单63、订单行66保持不变，5条该类异常恢复，不能产生重复或漏单。

## 回退

在替换生产解析服务前保留当前镜像标识；新镜像验证失败时只回退解析服务，其他容器和数据不动。
