# 面单覆盖回归守门设计

## 目标

把现场业务不变量固化为可重复执行的只读检查：每个已结束采集任务中，采集到的每张面单都必须进入识别结果，并最终归入正常行或异常行。

## 最小方案

- 新增一个后端脚本，复用现有采集读取、面单拆分和识别结果函数。
- 默认扫描全部已结束任务，也可指定任务 ID。
- 只输出任务 ID、数量、失败项和告警数量，不输出商品、收件人、快递单号或原始载荷。
- 硬失败时返回非零退出码：
  - 预期面单父记录数与识别父记录数不一致。
  - 某条原始采集记录没有任何识别结果。
  - 识别结果缺少原始采集来源。
  - 结果行没有归入正常或异常。
- 仅告警、不失败：
  - 同一父面单出现业务字段完全相同的子行。
  - 单张面单拆分超过 10 个子行。
- 告警绝不触发自动去重或自动修改结果。

## 边界

- 不增加 UI、接口、数据库表或依赖。
- 不修改解析、匹配、导出和规则包行为。
- 不连接或修改 5173 现场环境。
- 仅在测试数据库和 6173 数据副本执行。

## 验收

- 一条最小测试能证明遗漏父面单、来源丢失、未归类结果会被判为失败。
- 正常覆盖但含重复子行/高拆分的任务只产生告警。
- 现有后端测试全部通过。
- 6173 全量历史任务扫描无硬失败，输出不含业务原文。
