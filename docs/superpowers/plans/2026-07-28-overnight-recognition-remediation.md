# 夜间识别整改与阶段回退计划

## 不可突破的边界

- `5173` 是现场版本：不重启、不部署、不改数据、不改容器。
- 三台采集器和正在运行的现场进程不在本次范围内。
- 所有验证只使用 `6173` 和现有验证数据副本。
- 每一阶段必须同时具备：独立提交、Git 标签、独立镜像、验证记录。
- 任一阶段未通过，就保留上一阶段，不继续叠加不可验证的改动。

## 阶段

1. `stage-01`：现场基线与全量回归门禁。
2. `stage-02`：列出规则包中已生效和未生效字段。
3. `stage-03`：特殊单关键词由规则包控制。
4. `stage-04`：区分规则包缺失、规则包无效、解析服务不可用。
5. `stage-05`：把现有强制业务约束登记为规则包校验，并保留原有解析结果。
6. `stage-06`：在现有规则包页面编辑已生效的子规则，不开放原始 JSON 细节编辑。
7. `stage-07`：移除业务页面上的技术任务编号和人工修改/确认口径。
8. `stage-08`：6173 全量历史覆盖、接口、页面、日志和 Excel 合同验收。

## 每阶段验收

- 正常解析样本结果不变，除非该阶段明确修改对应规则。
- 多商品面单仍拆为多个商品行。
- 不按业务内容去重；重复打印全部保留。
- `采集面单数 = 正常覆盖面单数 + 异常覆盖面单数`。
- 未匹配商品不能进入正常供应商工作表。
- 正常表固定七列；异常表固定一列 `图片匹配文本`。
- 只部署到 `6173`，确认 `5173` 容器身份和运行时长没有变化。

## 明早回退方式

按 `ops/validation-stages/20260728-night/README.md` 从最新阶段向前逐级切换。每次只切换一个阶段，刷新 `6173` 验证；不操作 `5173`。
