# cargo-platform 现场收口与规则驱动整改计划

## 目标

保留当前现场业务流程，只整改识别、匹配、采集恢复和导出背后的规则与可靠性。
业务员只负责开始采集、结束采集、查看异常和下载 Excel；管理员维护规则包、匹配
规则和商品资产。禁止恢复手工编辑、确认、排除订单行的路线。

## AI 自适应识别最终目标（2026-07-31 重新定稿）

### 结论

可以实现，但必须把 4B 模型限制在“小孩也能完成”的工作内：模型只读取租户选中的
少量脱敏证据片段，为五字段选择对应片段；AI 服务再映射成一个或多个五字段商品行。
片段编号属于内部防幻觉协议，用户和平台只接收五字段。模型不写规则、不看地址、
不接触商品、SKU、图片、档口和 Excel。管理员修改的是一次性的学习样本，不是最终业务订单行。
确定性规则编译器根据原始字段、管理员确认结果和格式指纹生成声明式规则，验证通过
后才加入规则包并重跑原始面单。

当前 6173 的 46 条规则使用了 5173 结果作为输入并由脚本批量确认，只能证明规则
编译和回放引擎可用，不能作为 AI 学习能力验收。该结果必须标记为
`oracle_seeded_not_ai`，保留为引擎回归基线，但从纯 AI 验收结果中排除。

### 可实现边界

- 已授权且存在可读商品字段的面单指纹：可以自适应不同文本格式。
- 已学格式：只运行声明式规则，不调用 AI；AI 掉线不影响业务。
- 新文本格式：AI 只生成 `商品、销售属性1、销售属性2、数量、备注`，管理员可修正。
- 多商品面单：AI 返回多行，规则也必须稳定复现相同拆分；不得合并或去重。
- 全新原始数据结构：先由开发者增加指纹适配器和可选字段，不能让 AI 猜任意载荷。
- 加密、不可读或租户未选择足够字段：进入可处理异常，绝不猜测或静默丢失。
- 本阶段不做 OCR。

### 固定模块边界

1. **指纹能力层（代码资产）**
   - 开发者维护指纹检测、原始字段清单、XML/JSON 转纯文本能力。
   - 租户管理员只选择授权指纹中哪些字段用于展示和 AI 识别。
   - 修改租户字段选择不改写已经生效的规则。
2. **证据预处理层（确定性）**
   - 只输出 `{原始路径、中文名称、实际值}`。
   - 去除未选择字段和敏感信息，生成格式指纹与文本语法签名。
3. **本地 AI 候选层**
   - 输入只有预处理证据和五字段输出契约。
   - 模型内部只选择证据片段，服务对外只输出一个或多个五字段商品行。
   - 内部片段编号不得出现在用户页面、规则包或业务结果中，不允许输出规则代码。
4. **管理员学习层**
   - 管理员可修改五字段、增加或删除商品行。
   - 确认结果保存为学习样本，不直接覆盖业务结果。
5. **规则编译与校验层（确定性）**
   - 从白名单操作中编译声明式规则并绑定指纹、语法签名和字段路径。
   - 必须精确复现确认样本，不能命中不同格式；歧义时要求再确认一张，不保存坏规则。
6. **规则运行层**
   - 同格式新面单只走规则，自动重跑解析、匹配和导出。
   - 失败进入异常页，不能回退到隐藏解析或人工订单行覆盖。

### 真实验收的数据隔离

- 学习期间，AI、后端和规则编译器不得挂载或读取 5173 标准答案。
- 5173 的 Excel 结果只保存在独立只读评分区，完成一轮运行后才由比较器读取。
- 管理员确认必须来自真实页面操作；Codex 和批处理脚本不得代替管理员确认。
- 页面必须明确显示：`模型原始候选`、`管理员修改`、`编译器生成规则`、`规则自动复用`。

### 实施阶段

#### 阶段 A：建立纯 AI 基线

1. 备份当前 6173 平台库、AI 会话库、规则包和镜像。
2. 短暂停止仅 6173 的后端与 AI 服务，按 `workspace_id=1` 事务清空规则包、
   规则修订、AI 会话和派生解析结果；现有删除 API 不能完成真冷启动，不能使用。
3. 保留三轮原始面单、商品、SKU、图片、档口和匹配资产。
4. 补齐当前租户的指纹授权和字段选择，页面不得再显示“未获授权”。

**检查点 A：** 6173 显示 0 条规则、0 条学习记录、三轮原始面单数量不变；5173
容器、数据库和进程均未变化。清理前后必须保持：3 个采集任务、102 条原始记录、
23 个商品、2004 个 SKU、2360 个图片资产、6 个档口和 37 条商品匹配规则。

#### 阶段 B：打通一个真实格式

1. 选择一张陌生格式，页面展示模型实际收到的字段。
2. 4B 选择五字段对应证据，AI 服务返回五字段候选；失败时仍提供可编辑空行，
   不以技术报错阻断管理员。
3. 管理员确认或修改候选。
4. 编译器生成规则，精确回放确认样本后加入规则包。
5. 选择同格式留出面单自动复用，确认模型调用次数为 0。

**检查点 B：** 不使用标准答案输入，完成“陌生面单 → AI 候选 → 管理员确认 →
规则生成 → 同格式自动复用”的完整闭环。

#### 阶段 C：覆盖真实复杂度

- 依次验证 JSON 商品字段、XML 文本、嵌套标签、多商品、相同内容重复打印、特殊单、
  缺商品和不可读字段。
- 一个格式通过后再进入下一个格式，任何失败都保留上一阶段回退点。
- 对规则生成失败区分：字段不足、AI 候选无效、映射歧义、规则回放失败。

**检查点 C：** 每次确认产生可见规则包修订；任何打印都进入正常结果或明确异常。

#### 阶段 D：事后评分与发布门槛

1. 三轮任务完成后才启用独立比较器读取 5173 标准答案。
2. 分别统计模型五字段原始正确率、管理员修改率、规则编译成功率、留出复用正确率。
3. 正常供应商 Excel 的业务字段、行数、图片与 5173 基准一致。
4. 验证 AI 服务断开后，所有已学格式仍正常解析；陌生格式进入“AI 服务不可用”异常。
5. 6173 人工验收通过前不合并、不推送、不部署 5173。

### 最终交付门槛

1. `采集面单 = 正常面单覆盖 + 异常面单覆盖`，无去重、无漏单。
2. AI 输入与租户勾选字段完全一致，页面可核对。
3. AI 服务对外只返回五字段；字段名和内部片段编号不得混进字段值。
4. 管理员修正只形成学习样本，最终订单行必须由新规则重跑产生。
5. 坏规则不能保存；每条规则有样本、来源字段、修订和校验结果。
6. 同格式留出样本不调用 AI，并与冻结基准一致。
7. 规则 UI 默认展示业务摘要和验证状态；技术拆分步骤只放在折叠诊断区。
8. 已学规则在 AI 离线时继续工作。
9. 当前支持范围外的指纹显示“系统尚未支持该面单结构”，不伪装成普通识别失败。
10. 5173 全程不变，并保留逐阶段数据库、镜像和 Git 回退点。

## 不可破坏的验收口径

1. 一次采集任务是从“开始采集”到“结束采集”的完整一轮。
2. 统计面单数量，不把采集记录条数、任务次数或打印次数当成面单数量。
3. 同一轮采集内的每张面单都保留，不按内容去重。
4. 多商品面单必须拆成多个子商品行；不得把多个商品挤在一个字段里。
5. 每张面单最终必须进入正常结果或可处理异常，不能静默丢失。
6. 未匹配到商品的行不能进入正常报货表；只缺图片时仍可输出正常行。
7. 特殊单保留在异常面单，不要求业务员处理。
8. 识别错误通过规则包修复并重跑，不能手工修改结果行。
9. 正常 Excel 保持七个业务列；异常面单只保留“图片匹配文本”。

## 6173 交付收口补充（2026-07-30）

本轮只修复用户操作验收发现的两个 P0，不改变既有业务流程：

1. **覆盖闭环**
   - 解析未生成商品行的父面单也必须形成一条明确异常。
   - 采集面单数、正常覆盖数和异常覆盖数由同一后端结果计算。
   - 下载前由后端校验 `采集面单 = 正常覆盖 + 异常覆盖`；不相等时拒绝生成报货文件。
2. **错误行拦截**
   - 解析后的单个字段不得包含多行商品内容。
   - 数量标记不得残留在销售属性字段中。
   - 完整性不通过的结果进入 AI 待确认或解析异常，不能进入商品匹配和正常 Excel。
3. **用户入口统一**
   - 异常页逐张显示解析异常，不再只显示一个汇总数字。
   - 解析异常直接进入 AI 面单解析；商品和 SKU 异常仍进入各自维护页面。
   - 导出页显示覆盖状态，并在覆盖不完整时禁用下载。

实施顺序：先写失败测试，再修后端覆盖，再修解析完整性，最后调整 6173 页面并做真实副本验收。每一步单独提交；当前 `d5d2b64` 保留为总回退点。

## 整改顺序

### 阶段 0：现场版本收口

- 固定 Git 提交、镜像、数据备份、现场验收结果和回退命令。
- 任何后续改动都从独立分支和 6173 数据副本开始。

### 阶段 1：回归验收门槛

- 从历史副本选取多文档、多商品、相同内容、不可读、特殊单、缺图片和重连回放样本。
- 建立一条命令可运行的覆盖矩阵。
- 每次改动必须验证“面单数 = 已识别父单数”和“所有子行 = 正常覆盖 + 异常覆盖”。

### 阶段 2：识别规则包

- 独立识别服务只按启用的声明式规则包生成父面单和子商品行。
- 修复错误合并、错误拆分和新平台不支持问题。
- 无规则包、规则包无效、识别服务不可用必须显示不同的业务原因。

### 阶段 3：商品、SKU、图片匹配

- 管理员可为一条规则选择一个或多个商品行字段，任一字段出现关键词即命中。
- 未匹配商品进入异常；SKU 或图片问题按既定业务口径处理。
- 修改规则或资产后自动重跑受影响任务，不保存人工结果覆盖。

### 阶段 4：采集器可靠性

- 掉线重连后只补传本轮未送达数据。
- 新一轮采集不能把上一轮历史面单重新归入当前任务。
- 队列、心跳、重试和任务归属必须可诊断。

### 阶段 5：页面与导出收口

- 页面按“采集记录 → 面单解析 → 异常处理 → 导出中心”展示。
- 不把数据库 ID、技术任务号或“第几批”作为主要业务标签。
- 不出现订单行编辑、确认、排除或审批入口。

### 阶段 6：发布门槛

- 6173 副本验证通过后才允许合并。
- 合并后先建立数据备份和不可变镜像，再在停止采集的窗口切换。
- 部署后验证健康、采集器、代表任务、Excel 和日志；失败立即回退。
