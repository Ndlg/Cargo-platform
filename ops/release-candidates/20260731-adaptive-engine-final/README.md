# 6173 自适应面单引擎最终方案

本发布只落在隔离验证环境 `6173`。现场 `5173`、三台采集器和
`cargo-platform-data` 不在变更范围内。

## 交付链路

1. 采集模块保留每次打印，不按内容去重。
2. 租户管理员为已授权指纹选择允许传给 AI 的原始字段。
3. 本地 4B 模型只根据脱敏后的选定字段给出五字段候选：商品、销售属性 1、
   销售属性 2、数量、备注。
4. 管理员只修正学习样本，不编辑业务订单行。
5. 确定性编译器根据原始证据和修正样本生成声明式规则；独立 parser 必须在同一
   封存证据上重放一致，规则才可保存。
6. 已学规则直接复用；AI 掉线不影响已知格式。未知格式保留明确异常。
7. 商品匹配模块自动匹配商品、SKU、图片和档口；未命中项进入异常。
8. 导出模块只接收完整匹配行，生成七列供应商工作表和单列异常表。

4B 模型不是规则作者。它只是受限候选器；规则资产由确定性编译器生成，并受字段
快照、证据哈希、管理员权限和 parser 重放四道守门约束。

## 最终验收

- 真零规则输入：任务 64/65/66，共 `283` 张父面单。
- 管理员学习：`25` 个真实模型会话；模型整行完全一致 `0/25`，管理员修正率
  `100%`，证明业务正确性没有依赖 4B 猜测。
- 自动规则覆盖：`281/283`；剩余 `2` 张不可读商品面单明确进入异常。
- 最终结果：`293` 条商品/异常行，其中正常导出 `266`、异常 `27`。
- 封存答案仅在学习结束后用于评分；`263/266` 条正常核心行与 5173 对照一致。
  另外 `3` 条不是识别错误，而是 6173 从两张多商品面单原文中恢复出的遗漏子行：
  任务 64 第 90 张的第 2 件 `C6全黑 / 37 / 1`，以及任务 65 第 39 张的
  第 2、3 件 `Cloudtilt聯名1代中灰 / 40 / 1`、
  `Cloudtilt聯名2代黑色 / 40 / 1`。5173 对照结果只保留了各自第一件；按“多商品
  拆多行、不得漏单”合同，这三行必须保留。
- 任务 66 Excel：正常 `84` 行和 `84` 张图片，异常 `13` 行；表头合同通过。
- AI 停止后已学规则仍可解析，任务统计不变。
- 发布、回退、恢复三个节点数据库哈希完全一致，完整性检查通过。

机器可读的镜像、数据卷、哈希、覆盖和 5173 冻结证据见 `manifest.json`。
